# FreeCAD GUI Kiosk Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Opening the app lands the user in a full-window FreeCAD with the 4yi CAD panel docked — no visible remote-desktop chrome: no Fluxbox decorations/toolbar, no FreeCAD first-start/Start page, no noVNC control bar.

**Architecture:** All changes are baked into `Dockerfile.freecad-gui` + `scripts/freecad-gui/`: (1) Fluxbox `init`/`apps` files force FreeCAD maximized + undecorated and hide the toolbar; (2) a pre-seeded FreeCAD `user.cfg` sets 简体中文, suppresses the first-start wizard and the Start page; (3) a minimal `kiosk.html` (noVNC core RFB, no UI shell) is installed into the noVNC web root and `CAD_REMOTE_DESKTOP_BASE_URL` switches to it. Home dir is pod-ephemeral, so baked configs ARE the per-boot defaults. Verification is static (spike-test asserts) — real GUI verification happens on the next platform Release.

**Tech Stack:** Dockerfile, shell, Fluxbox config, FreeCAD FCParameters XML, noVNC 1.x ES-module RFB. No app/python changes.

`scripts/freecad-gui/kiosk.html` — minimal no-UI noVNC client (adapt module path to the image's novnc layout — Debian `novnc` package serves `core/rfb.js` at the web root; verify with `dpkg -L novnc` knowledge or the vendored tree; the page must take `path` from the query string, enable `resizeSession`, `scaleViewport` fallback, auto-reconnect):

```html
<!DOCTYPE html>
<html>
<head>
<meta charset="utf-8">
<title>4yi CAD</title>
<style>html,body,#screen{margin:0;padding:0;width:100%;height:100%;overflow:hidden;background:#1a1a1a}</style>
</head>
<body>
<div id="screen"></div>
<script type="module">
  import RFB from './core/rfb.js';
  const params = new URLSearchParams(window.location.search);
  const path = params.get('path') || 'websockify';
  const proto = window.location.protocol === 'https:' ? 'wss' : 'ws';
  const url = `${proto}://${window.location.host}/${path}`;
  let rfb;
  function connect() {
    rfb = new RFB(document.getElementById('screen'), url);
    rfb.resizeSession = true;
    rfb.scaleViewport = true;
    rfb.addEventListener('disconnect', () => setTimeout(connect, 2000));
  }
  connect();
</script>
</body>
</html>
```

`scripts/freecad-gui/start-freecad-gui.sh` — before launching FreeCAD, seed the config for BOTH candidate config dirs (FreeCAD 1.0 uses `~/.config/FreeCAD/user.cfg`; older reads `~/.FreeCAD/user.cfg` — the image already creates `.FreeCAD/Mod`):

```sh
seed_freecad_user_cfg() {
  local template="/usr/local/share/4yi-cad/freecad-user.cfg"
  [ -f "$template" ] || return 0
  for dir in "$HOME/.config/FreeCAD" "$HOME/.FreeCAD"; do
    mkdir -p "$dir"
    [ -f "$dir/user.cfg" ] || cp "$template" "$dir/user.cfg"
  done
}
```

Call it in the startup sequence (near the existing mkdir block). Guarded by file-exists so legacy images/modes unaffected.
